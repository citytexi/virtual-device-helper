# M3-2a — 로그 코어 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`(권장) 또는
> `superpowers:executing-plans`로 task 단위 구현. 각 단계는 체크박스(`- [ ]`)로 추적한다.

**Goal:** main이 연결된 기기마다 logcat을 계속 받아 버퍼에 쌓고, renderer에는 로그 전용 포트로 나르며,
`log_read`는 패키지로 걸러 크래시한 앱의 로그도 준다.

**Architecture:** `src/main/logs/`에 순수 모듈 셋(`logClock`, `logBuffer`, `pidTracker`)과 프로세스를 다루는 둘
(`logTail`, `logManager`)을 둔다. `logManager`는 registry 이벤트로 기기별 tail을 켜고 끄며, `MessageChannelMain`
포트로 버퍼를 전달한다. MCP 툴 층은 `ToolContext.pidHistory` 함수 하나로만 로그 쪽을 본다.

**Tech Stack:** TypeScript, Electron `MessageChannelMain`, adb logcat, zod 4, `@modelcontextprotocol/sdk` 1.30, Vitest

**Spec:** [`../specs/2026-09-28-m3-node-control-logs-events.md`](../specs/2026-09-28-m3-node-control-logs-events.md)
— "log_read", "로그 파이프라인", "로그 포트 메시지", "로그 tail 상태" 절. 결정 근거는
[ADR-0013](../../adr/0013-log-transport-dedicated-port.md).

**선행 조건:** 없다. M3-1과 독립이다. [M3-2b](2026-09-28-m3-2b-log-panel.md)가 이 계획의 포트와 타입에 기댄다.

## Global Constraints

- 답변·주석·문서는 한국어로 쓴다. 기술 용어·API 이름·명령어·에러 문자열은 원문 그대로 둔다.
- 버퍼 상한은 기기당 5만 줄, 배치 간격은 100ms, snapshot 청크는 5000줄이다. 상수로 두고 테스트가 값을 바꿀 수 있게 주입한다.
- tail 첫 시작은 인자 `['logcat','-v','threadtime','-T','2000']`, 재시작은 `['logcat','-v','threadtime','-T','<마지막 timestamp>']`다. timestamp를 따옴표로 감싸지 않는다. `adbClient.stream`은 셸 없이 adb를 띄우고 adb가 인자마다 이스케이프한다(`androidDevice.ts`의 `readLogs`가 이미 이렇게 넘긴다). 재시작 간격은 `streamManager.ts`의 `RECONNECT_DELAYS_MS`를 그대로 쓴다.
- tail과 버퍼의 수명은 기기 연결을 따른다. 포트는 전달만 맡는다. 포트를 닫아도 버퍼는 남는다.
- preload는 `app:log-port`로 온 포트가 정확히 하나일 때만 main world로 넘긴다. 범용 포트 통로를 만들지 않는다.
- MCP 툴 층(`src/main/mcp/`)은 `src/main/logs/`와 adb를 import하지 않는다. `ToolContext`에는 함수 시그니처만 둔다. `layering.test.ts`의 금지 목록에 `src/main/logs`를 더해 기계적으로 막는다(Task 6).
- adb 호출의 reject는 로그 기능을 멈추지 않는다. `pidof`·`ps` seed·`date` 측정이 실패하면 각각 빈 결과·seed 없음·수신 시각 폴백으로 간다.
- 기기가 끊기면 그 기기의 로그 포트에 `status: 'stopped'`를 보내고 포트를 닫는다. 다시 붙은 기기는 `seq` 0부터 새 버퍼다.
- `log_read`의 응답 모양은 ADR-0008 그대로다.
- 새 npm 의존성을 들이지 않는다.
- 각 task 끝에서 `npm test`와 `npm run typecheck`가 통과해야 한다. 바뀐 모양 때문에 깨지는 기존 테스트는 같은 task에서 고친다.
- 문서에는 라인번호, 파일·툴 개수, 진행률을 적지 않는다. 파일명과 심볼명으로 가리킨다.
- 문서를 고치면 `python3 docs/script/docs.py lint`와 `python3 docs/script/docs.py links`를 돌린다.
- 커밋 메시지는 한국어 Conventional Commits(`feat(logs): ...한다`)이고, 끝에 다음 줄을 붙인다:
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`

## Review Focus

- **크래시로 죽은 앱**: 프로세스가 사라진 뒤에도 `log_read({ package })`가 크래시 스택을 줘야 한다. `pidof`만 보면 빈 결과가 된다. → Task 3, Task 6 테스트.
- **tail 재시작 경계의 중복**: `-T <ts>` 재시작은 같은 밀리초 줄을 다시 준다. 버퍼에 같은 줄이 두 번 들어가면 안 된다. → Task 2 테스트.
- **renderer가 사라진 포트**: 창 reload로 포트 반대쪽이 닫혀도 타이머와 전송이 멈추고 버퍼는 남아야 한다. → Task 5 테스트.
- **연말 연초의 timestamp**: 12월 31일 줄을 1월 1일 호스트가 받으면 작년으로 해석해야 한다. → Task 1 테스트.
- **pid 재사용**: 같은 pid를 다른 앱이 이어 받아도 이미 받은 줄의 `pkg`는 바뀌지 않아야 한다. → Task 3 테스트.

### Task 3: pid→패키지 추적

**Files:**
- Create: `src/main/logs/pidTracker.ts`
- Test: `src/main/logs/pidTracker.test.ts`

**Interfaces:**
- Consumes: `LogLine`
- Produces:
  - `packageFromProcessName(name: string): string` — 첫 `:` 앞
  - `createPidTracker(): PidTracker`
  - `interface PidTracker {`
    `seed(psStdout: string): void` — `ps -A -o PID,NAME` 출력
    `observe(line: LogLine): boolean` — `Start proc` 줄이면 맵을 갱신한다. 새 패키지가 생겼으면 true.
    `packageOf(pid: number): string | undefined`
    `pidsOf(pkg: string): number[]` — 이 연결 동안 그 패키지가 가진 pid 전부, 죽은 pid 포함
    `packages(): string[]` — 정렬
    `}`

- [ ] **Step 1: 실패하는 테스트를 쓴다**

```ts
const ps = '  PID NAME\n    1 init\n 8383 com.android.settings\n 7601 com.android.chrome:sandboxed_process0:org.chromium.content.app.SandboxedProcessService0:29\n'
const start = (pid: number, proc: string): LogLine => ({
  timestamp: '09-28 10:00:00.000', level: 'I', tag: 'ActivityManager', pid: 500,
  message: `Start proc ${pid}:${proc}/u0a123 for top-activity {${proc.split(':')[0]}/.Main}`
})

it('strips the process suffix', () => {
  expect(packageFromProcessName('com.android.chrome:sandboxed_process0:x:29')).toBe('com.android.chrome')
})
it('seeds from ps', () => {
  const t = createPidTracker(); t.seed(ps)
  expect(t.packageOf(8383)).toBe('com.android.settings')
  expect(t.packageOf(7601)).toBe('com.android.chrome')
})
it('learns a started process and reports a new package', () => {
  const t = createPidTracker()
  expect(t.observe(start(9000, 'com.example.app'))).toBe(true)
  expect(t.observe(start(9001, 'com.example.app:remote'))).toBe(false)
  expect(t.pidsOf('com.example.app')).toEqual([9000, 9001])
})
it('keeps a dead pid in history after the pid is reused', () => {
  const t = createPidTracker()
  t.observe(start(9000, 'com.example.app'))
  t.observe(start(9000, 'com.other'))
  expect(t.packageOf(9000)).toBe('com.other')
  expect(t.pidsOf('com.example.app')).toEqual([9000])
})
it('ignores Start proc from other tags', () => {
  const t = createPidTracker()
  expect(t.observe({ ...start(9000, 'com.x'), tag: 'Fake' })).toBe(false)
  expect(t.packageOf(9000)).toBeUndefined()
})
```
