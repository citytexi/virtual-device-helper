# M3-2b — 로그 패널 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`(권장) 또는
> `superpowers:executing-plans`로 task 단위 구현. 각 단계는 체크박스(`- [ ]`)로 추적한다.

**Goal:** 작업 영역에 "로그" 탭을 더해 활성 기기의 logcat을 실시간으로 보여 주고, 레벨·텍스트·정규식·태그·앱으로
거르게 한다.

**Architecture:** renderer는 `app:log-port`로 받은 포트를 `useLogStream` 훅 하나가 관리한다. 훅은 받은 줄을
5만 줄 버퍼에 쌓고 탭 가시성에 따라 `pause`·`resume`을 보낸다. 필터와 가상 스크롤 범위 계산은 순수 함수로 떼어
테스트한다. `LogTab`은 고정 높이 행으로 보이는 범위만 그린다.

**Tech Stack:** TypeScript, React 19, Vitest, @testing-library/react, jsdom

**Spec:** [`../specs/2026-09-28-m3-node-control-logs-events.md`](../specs/2026-09-28-m3-node-control-logs-events.md)
— "로그 포트 메시지", "로그 탭" 절.

**선행 조건:** [M3-2a](2026-09-28-m3-2a-log-core.md)가 끝나 있어야 한다. 이 계획은 M3-2a의 `LogEntry`, `LogDown`,
`LogUp`, `LogPortMeta`(`src/shared/types/logs.ts`), `RendererApi.openLogs`·`closeLogs`, `IPC_CHANNELS.logPort`를 쓴다.

## Global Constraints

- 답변·주석·문서는 한국어로 쓴다. 기술 용어·API 이름·명령어·에러 문자열은 원문 그대로 둔다.
- renderer 버퍼 상한은 5만 줄이다(main과 같다). `gap`은 버퍼 안에 "밀려난 구간" 행으로 들어간다.
- 로그 탭은 활성 기기(`useAppState.ts`의 `targetSerial`)를 따라간다. 활성 기기가 바뀌면 옛 포트를 닫고 새로 연다.
- 탭이 숨겨지면 `pause`, 보이면 `resume { afterSeq: 마지막으로 받은 seq }`를 보낸다.
- 필터는 전부 renderer에서 적용한다. 필터를 바꾸면 버퍼 전체를 다시 거른다.
- 행 높이는 고정이고 메시지는 한 줄로 자른다. 가상 스크롤은 직접 만든다. 새 npm 의존성을 들이지 않는다.
- 탭 순서는 활동 → 로그 → 에이전트다. WAI-ARIA tabs 패턴(`WorkArea.tsx`)을 그대로 쓴다.
- 스타일은 `app.css`의 기존 토큰만 쓴다.
- 각 task 끝에서 `npm test`와 `npm run typecheck`가 통과해야 한다. 바뀐 텍스트·role 때문에 깨지는 기존 테스트는 같은 task에서 고친다.
- 문서에는 라인번호, 파일·툴 개수, 진행률을 적지 않는다. 파일명과 심볼명으로 가리킨다.
- 문서를 고치면 `python3 docs/script/docs.py lint`와 `python3 docs/script/docs.py links`를 돌린다.
- 커밋 메시지는 한국어 Conventional Commits(`feat(renderer): ...한다`)이고, 끝에 다음 줄을 붙인다:
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`

## Review Focus

- **기기 전환 직후 늦게 온 메시지**: 옛 포트의 `batch`가 새 기기 목록에 섞이면 안 된다. → Task 1 테스트.
- **초당 수백 줄**: 배치마다 버퍼 전체를 복사하면 스크롤이 멈춘다. 버퍼 갱신과 필터 재계산이 새 줄만큼만 일해야 한다. → Task 2·3 테스트.
- **잘못된 정규식 입력 중**: `[`처럼 입력 도중의 정규식이 예외로 탭을 깨면 안 된다. 텍스트 필터만 꺼진다. → Task 2 테스트.
- **위로 스크롤해 읽는 중 새 줄**: 읽던 위치가 밀려 내려가면 안 된다. 따라가기가 멈춰야 한다. → Task 3 테스트.
- **활성 기기 없음**: 기기가 없으면 포트를 열지 않고 빈 안내를 보여야 한다. → Task 1·3 테스트.

- [ ] **Step 3: 구현한다**

- 필터 결과는 `useMemo`로 `[stream.version, filter]`에 묶는다. 필터가 그대로면 이전 결과 뒤에 새 줄만 걸러 붙이고, 앞쪽이 버퍼에서 잘렸으면 결과 앞에서도 같은 `seq`까지 잘라 낸다. 필터가 바뀌면 전체를 다시 거른다.
- 행은 `LOG_ROW_HEIGHT` 고정, `position: absolute; top: index * LOG_ROW_HEIGHT`. 전체 높이는 `count * LOG_ROW_HEIGHT`.
- 따라가기 판정: `scrollTop + clientHeight >= scrollHeight - LOG_ROW_HEIGHT`.
- 행 표시: 시각(`timestamp`의 `HH:mm:ss.SSS`), 레벨 글자, 태그, 메시지 한 줄. 레벨 `E`·`F`는 `--danger`, `W`는 `--warn` 색.
- `WorkArea`의 `TABS`에 `{ id: 'logs', label: '로그' }`를 활동과 에이전트 사이에 넣고, 패널에 `<LogTab serial={targetSerial(snapshot)} visible={selected === 'logs'} />`.
- 로그 탭 패널은 `.tabpanel`의 `overflow-y: auto` 대신 내부 목록이 스크롤하도록 `display: flex; flex-direction: column`.

- [ ] **Step 1: M3-2b 완료 조건을 확인한다**

`npm run dev`로 앱을 띄운다.
1. 설정 앱을 띄우고 `adb shell am crash com.android.settings`. 로그 탭 앱 필터에서 `com.android.settings`를 고르면 크래시 스택이 보인다. `pidof`가 빈 뒤에도 보인다.
2. `adb shell 'while true; do log -t M3LOAD load; done'`을 30초 돌리는 동안 스크롤·필터 입력·탭 전환이 멈추지 않는다.
